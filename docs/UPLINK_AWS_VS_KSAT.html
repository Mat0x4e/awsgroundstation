Uplink to a satellite: AWS Ground Station vs KSAT

Compiled 2026-11-19. Amazon Web Services (AWS) facts come from the AWS user guide (linked). Kongsberg Satellite Services (KSAT) publishes far less, so several KSAT points are marked [unverified] and must be confirmed in the KSAT interface control document (ICD) and quote. Diagrams: docs/diagrams/uplink-aws-groundstation.yaml and docs/diagrams/uplink-ksat.yaml (awsdac v0.23), rendered to docs/diagrams/out/.

0. Prerequisite common to both: you need your own satellite

Neither provider lets you transmit to a satellite you do not operate. The public broadcast satellites this project receives (NOAA-20, NOAA-21, Suomi National Polar-orbiting Partnership (SNPP), Terra) are downlink-only: AWS states that you cannot uplink to them (onboard satellite). Amateur satellites are a separate route, covered in docs/SATELLITES_PBS_AND_UPLINK.md.

What the operator must bring in both cases:

Item Requirement
Spacecraft receiver S-band telecommand (TC) receiver/transponder. AWS sites transmit only in 2025-2110 MHz (see section A1); KSAT S-band uplink is in the same space-operations band [unverified: exact KSAT range per site]
Command protocol Consultative Committee for Space Data Systems (CCSDS) TC (TC frames, communications link transmission unit (CLTU)) is the de facto standard; on-board authentication/encryption (CCSDS Space Data Link Security (SDLS)) strongly recommended, since the ground link is shared infrastructure. Details: Appendix A
Frequency rights International Telecommunication Union (ITU) filing for the space station through the national administration (in France, the national frequency agency (ANFR)), plus the national space operations authorization (French Space Operations Act). Each ground station country then licenses the earth station to transmit: AWS and KSAT both file these site licences, using the operator's data
Ephemeris North American Aerospace Defense Command (NORAD) identifier (ID) and a Space-Track two-line element set (TLE) at minimum; precise Orbit Ephemeris Message (OEM) ephemeris recommended, especially in launch and early orbit phase (LEOP)
Mission control software (MCS) Builds and logs commands, decodes telemetry. Open-source: Yet Another Mission Control System (YAMCS), OpenC3 COSMOS, National Aeronautics and Space Administration (NASA) F' ground system. Commercial: Kratos EPOCH and others

Case A - AWS Ground Station

A1. What AWS provides and what it does not

AWS rents the antenna and the radio frequency (RF) chain. It does not modulate your commands. The AntennaUplinkConfig only carries a spectrum config (centre frequency, polarization), a target effective isotropic radiated power (EIRP) and an optional transmitDisabled flag (application programming interface (API)). The data you send to it must already be digitized RF: VMEbus International Trade Association radio transport standard 49 (VITA-49) Signal Data/Internet Protocol (IP) (in-phase and quadrature (IQ) samples) (data plane interfaces). So the modulator (and the telemetry (TM) demodulator, unless you use demod/decode) runs as software on your Elastic Compute Cloud (EC2).

Uplink capability, identical at all sites (site capabilities):

Value
Frequency The API accepts a centre frequency of 2025-2120 MHz (UplinkSpectrumConfig), as do the frequently asked questions (FAQ) and NASA's 2026 State of the Art (SOA) report; the site capability table says 2025-2110. Design for 2025-2110, the ITU space-operation Earth-to-space band that every site is licensed for
Bandwidth up to 40 MHz
Polarization Right-hand circular polarization (RHCP) or left-hand circular polarization (LHCP), one at a time
EIRP 20-50 dBW
Uplink echo 2 MHz, same frequency range: a copy of what the antenna actually radiated, returned to your endpoint to verify commands

Uplink is synchronous only: Simple Storage Service (S3) delivery is downlink-only (dataflow paths).

A2. Hardware requirements

No ground hardware. On AWS:

  • Modem / agent EC2 in a public subnet with an Elastic IP. The recommended path is the AWS Ground Station Agent with a DataflowEndpointGroupV2, which now supports uplink (UplinkAwsGroundStationAgentEndpoint) as well as downlink, on the same instance (dataflow endpoint group (DFEG) versions). The agent needs dedicated cores and one of the listed instance types; the smallest is m5.8xlarge (32 vCPU, 100 MHz aggregate), common choices c5.12xlarge / c7i.12xlarge (instance types). Operating system (OS): Amazon Linux 2023 (recommended) or Amazon Linux 2 (AL2). The legacy alternative is a DataflowEndpoint with the AWS "dataflow endpoint application" Amazon Machine Image (AMI) (private AMI shared after onboarding), which also supports uplink.
  • MCS EC2 (small, private subnet, always on).
  • Optional: a lab RF test set or engineering model of the transponder. AWS has no test RF station; the digital twin (A5) does not carry data.

If you do not want to own the modem, AWS ground station as a service (GSaaS) partners resell AWS antennas with a managed modem in front: Skynopy (Paris) runs virtualized modems over AWS Ground Station, and EnduroSat lists "AWS GS (Skynopy)", that is AWS Ground Station (GS) through Skynopy, as a compatible network for its S-band radio (Skynopy profile, EnduroSat). KSAT can also sell AWS antennas (see the side-by-side section). Prices: quote.

A4. AWS resources

  • Virtual private cloud (VPC), public subnet + Elastic IP address (EIP) for the agent, security group allowing User Datagram Protocol (UDP) from the com.amazonaws.global.groundstation prefix list on the DFEG ports and Transport Layer Security (TLS) 443 out (agent requirements).
  • KMS key (agent data encryption), Identity and Access Management (IAM) role for Ground Station.
  • Configs: TrackingConfig, AntennaUplinkConfig, UplinkEchoConfig, downlink config (AntennaDownlinkConfig or AntennaDownlinkDemodDecodeConfig), DataflowEndpointConfig (set dataflowEndpointRegion; see the steering note on 0-contact profiles), optional TelemetrySinkConfig to Kinesis.
  • Mission profile with edges: DataflowEndpoint(uplink) -> AntennaUplink, UplinkEcho -> DataflowEndpoint, AntennaDownlink -> DataflowEndpoint.
  • DFEG must be HEALTHY before a contact can be scheduled.

A5. Architecture

Command path: operator -> MCS -> TC frames -> software modem -> VITA-49 IQ (UDP, encrypted by the agent) -> antenna -> S-band. The uplink echo and the TM downlink come back to the same agent.

A6. Onboarding

  1. Prerequisite: your ITU filing (and Federal Communications Commission (FCC) filing if relevant) and your satellite operating licence must already exist; AWS only licenses its earth stations.

  2. Satellite Onboarding Questionnaire in the console, non-disclosure agreement (NDA), technical validation. AWS returns a licensing cost estimate per location; after you approve, it files with each regulator. AWS's own non-binding estimates (FAQ):

    Country Licensing time
    Ireland 45 days
    Sweden 3+ months
    United States 3+ months
    Chile, South Africa 3-6 months
    Bahrain, Singapore 6+ months
    Australia 9+ months

    AWS gives no updates between filing and the regulator's decision. For a European mission, Ireland 1 and Stockholm 1 are the fastest to license.

  3. Digital twin (optional): exact copies of the ground stations for scheduling, config and EventBridge testing, without licence or antenna use. It does not support data delivery, so it cannot test the modem or the RF link (digital twin).

  4. First live contacts with transmitDisabled: true and uplink echo, then real transmission.

This account's Cost Explorer (Jan-Nov 2026) matches exactly: Stockholm 1, Ohio 1 and Oregon 1 billed $10/min, Hawaii 1 $15/min (10 min = $150).

The Price List carries on-demand terms only. Reserved rates are no longer published. The last public figures (March 2022 pricing page) were $3/min narrowband and $10/min wideband reserved, with a minimum of 150 min/month for 12 months; reserved contacts cancelled more than 24 h ahead were free. Treat $3/min as a historical reference until the account team quotes.

Other billing rules from the FAQ and pricing history:

  • On-demand contacts can be booked 15 min to 7 days ahead. Cancelling an on-demand contact costs 100% of its price.
  • One contact is one metered line (usage type <site>-Contact-<band>-Minute), whatever the number of dataflows. An uplink + S-band TM contact is therefore one narrowband charge, not two. [unverified] Whether the 40 MHz threshold applies to each dataflow or to their sum. It only matters if the downlink in the same contact is wide (for example 50+ MHz X-band through the agent), which would bill the whole contact at the wideband rate.
  • Site licensing is not free: AWS sends a cost estimate per location before it files (FAQ). Amounts are not published.

Case B - KSAT (KSATlite)

B1. What KSAT provides

KSATlite is KSAT's automated ground-segment-as-a-service for small satellites: 26 stations and 150+ antennas of 3.7-6.1 m (product page; a 2026 KSAT article says nearly 35 stations and 200 antennas, the figure another KSAT article gives as the 2028 target), S-band up and down, X-band and Ka-band down, representational state transfer (REST) machine-to-machine scheduling, a customer portal, anomaly detection and 24/7 operations at the Tromso Network Operations Centre (KSATlite, operations). The full KSAT network is larger (300+ antennas, ~28 sites) and includes Svalbard and Troll, which see a polar low Earth orbit (LEO) satellite on every orbit.

The key difference with AWS: KSAT owns the modem. You send command frames (or ready-made CLTUs, depending on the ICD), KSAT modulates and radiates them. Your waveform must be one KSAT's baseband supports. Stage-by-stage comparison: TC data pipeline.

KSAT also offers satellite operations as a service (including LEOP), spectrum and licensing support, a test lab, and a portable "suitcase" ground station shipped to you for compatibility testing before launch (onboarding).

B2. Hardware requirements

None at the ground station. Operator side: an MCS host (on AWS or on premises) and a secure network path to KSAT. Before launch, the spacecraft (or its flatsat/engineering model) goes through RF compatibility testing with the KSAT test lab or the portable station.

B4. Architecture

Command path: operator -> MCS -> TC frames over the VPN -> KSAT modem -> antenna -> S-band. TM frames return the same way; payload data can be delivered to your cloud storage.

B5. Onboarding

Contract and ICD, frequency data for site licensing (KSAT supports the applications), network integration, RF compatibility test, then pass booking. KSAT publishes no durations [unverified]; site licensing is usually the longest item for both providers.

B6. Cost

KSAT has no public rate card. A third-party comparison reports per-pass or per-minute pricing and no upfront commitment for KSATlite (Woodrow Scientific, Oct 2026); GSaaS S/X-band rates generally start around $3/min (Payload).

TC data pipeline - from command to spacecraft

Both cases share the same top and bottom of the pipeline: the operator builds and secures the command, the spacecraft decodes and executes it. What differs is the middle: where the CLTU becomes a radio signal, and who handles it on the way. Protocol details are in Appendix A.

Your MCS Everything Everything
Ground network in transit Encrypted IQ (agent + KMS) Encrypted CLTUs (VPN)
Ground station provider equipment Decrypted IQ at the antenna site: demodulating it recovers the CLTUs Plain CLTUs in the KSAT baseband

The transport encryption of each provider (agent KMS key, VPN) protects the ground segment only. The space link itself is protected only by SDLS (or an equivalent on-board scheme).

Size of one command along the pipeline

Example: 20 octets of command parameters, one Space Packet per frame, SDLS Advanced Encryption Standard in Galois/Counter Mode (AES-256-GCM) with a 12-octet IV, a 16-octet message authentication code (MAC) - the built-in Yamcs profile - and BCH coding.

Stage Without SDLS With SDLS
Space Packet (6-octet header + 20) 26 octets 26 octets
TC frame: 5 header + 1 segment header + data + 2 cyclic redundancy check (CRC); SDLS adds 14 security header + 16 MAC 34 octets 64 octets
CLTU: 2 start + 8 per 7-octet codeblock + 8 tail 5 codeblocks, 50 octets 10 codeblocks, 90 octets
Air time at 4 kbps (classic TC rate) 0.10 s 0.18 s
Air time at 64 kbps 6 ms 11 ms
What crosses the ground network to the antenna Case A: continuous IQ stream for the whole contact, set by the sample rate (MB/s), independent of command size. Case B: the 50 or 90 octet CLTU plus SLE/TCP overhead same

The SDLS overhead (30 octets per frame) dominates a tiny command but is under 3% of a 1,024-octet frame. Acquisition and idle sequences (PLOP) add a mission-specific preamble per uplink session, not shown.

Both can be combined: since July 2025 KSAT is part of the AWS Ground Station as a Service Partner Program and can offer AWS Ground Station antennas alongside its own (AWS blog).

Choosing

  • AWS fits a team that already operates on AWS, wants pay-per-minute with no contract, and can own a software modem (or buy one). Most of the effort is in the modem and its validation.
  • KSAT fits a mission that needs polar coverage, LEOP support or a managed modem, and accepts a contract and an ICD. Most of the effort is in contracting, ICD and network integration.
  • In both cases the long pole is the frequency filing and site licences, not the cloud set-up.

Appendix A - CCSDS telecommand and SDLS

CCSDS standards are free from the CCSDS Blue Books. European Space Agency (ESA) missions apply them through the European Cooperation for Space Standardization (ECSS) standards of the ECSS-E-ST-50 series. Issue numbers below are those referenced by CCSDS 355.0-B-2 (July 2022); check for newer issues before baselining.

A.1 The TC stack

Layer Standard Role
Application / network Space Packet Protocol, CCSDS 133.0-B Carries one command (or file segment) to an on-board application, addressed by application process identifier (APID)
Data link - security Space Data Link Security (SDLS), CCSDS 355.0-B-2; key and security association (SA) management in SDLS Extended Procedures, CCSDS 355.1-B-1; algorithms in CCSDS 352.0-B-2 Authentication, encryption or both, inside the transfer frame
Data link - protocol TC Space Data Link Protocol, CCSDS 232.0-B-4; retransmission by COP-1, CCSDS 232.1-B Framing, virtual channels, reliable in-order delivery
Synchronization and channel coding TC Synchronization and Channel Coding, CCSDS 231.0-B BCH or LDPC coding, randomization, CLTU, physical layer procedures
Physical Radio Frequency and Modulation Systems, CCSDS 401.0-B Carrier, modulation, frequency band
Ground cross-support Space Link Extension Forward CLTU (F-CLTU), CCSDS 912.1-B; Return All/Channel Frames for TM How a mission control centre hands CLTUs to someone else's ground station

The newer Unified Space Data Link Protocol (USLP, CCSDS 732.1-B) can replace TC, TM and Advanced Orbiting Systems (AOS) frames with a single format; SDLS applies to it as well.

A.2 Space Packet

  • 6-octet primary header: version (3 bits), type (1 = telecommand), secondary header flag, APID (11 bits, the on-board destination), sequence flags (2 bits), sequence count (14 bits), data length (16 bits).
  • Optional secondary header (for example a time tag or a Packet Utilisation Standard (PUS) service/subservice, as used by ESA's Packet Utilisation Standard ECSS-E-ST-70-41).
  • User data: the command parameters, usually with a packet error control CRC.

A.3 TC Transfer Frame and COP-1

  • 5-octet primary header: version (2 bits), bypass flag, control command flag, spare, spacecraft ID (10 bits), virtual channel ID (6 bits), frame length (10 bits), frame sequence number (8 bits). Maximum frame length 1,024 octets.
  • Optional 1-octet segment header (multiplexer access point (MAP) identifier and sequence flags) to multiplex or segment packets. Yamcs does not segment, so one packet must fit in one frame.
  • Optional 2-octet Frame Error Control Field (CRC-16).
  • Three frame types:
    • Type-A data (AD): sequence-controlled. The on-board FARM-1 accepts only the next expected frame sequence number, so frames arrive once, in order.
    • Type-B data (BD): expedited. Bypasses FARM-1 acceptance checks. Used for recovery commands when the sequence state is lost.
    • Type-B control (BC): COP-1 directives such as Unlock and Set V(R).
  • COP-1: the ground FOP-1 keeps a sliding window of unacknowledged AD frames and retransmits them (go-back-N) on timeout or request. The on-board FARM-1 reports its state in the CLCW (Communications Link Control Word, 4 octets) carried in the Operational Control Field of every TM frame: report value N(R), and the Lockout, Wait, Retransmit, No RF Available and No Bit Lock flags. The uplink therefore depends on a working downlink for acknowledgement.

A.4 CLTU and channel coding

  • BCH(63,56) codeblock: 7 information octets plus 7 parity bits and 1 filler bit = 8 octets. It corrects single-bit errors in each codeblock (or detects errors in a detect-only mode).
  • LDPC (128,64) and (512,256) codes, added in later issues of 231.0-B, give several dB more coding gain; the spacecraft receiver must support them.
  • CLTU = start sequence EB90 + codeblocks + tail sequence (C5C5C5C5C5C5C579 for BCH). An optional pseudo-randomizer is applied before coding to guarantee bit transitions.
  • Physical layer operations procedures (PLOP-1, PLOP-2) define the order on the carrier: carrier only, acquisition sequence (alternating 0/1 for bit lock), CLTUs, idle sequence between CLTUs, carrier off. PLOP-2 keeps the carrier up between CLTUs.

In Case A your modem implements all of A.4 plus modulation. In Case B KSAT does the modulation and PLOP; whether it also does the coding is an ICD question.

A.5 Modulation (CCSDS 401)

  • Classic agency TC: PCM/PSK/PM on an 8 or 16 kHz sine subcarrier, typically 1-4 kbps (some missions use higher rates).
  • Higher-rate and NewSpace radios: direct carrier modulation such as BPSK, offset quadrature phase-shift keying (OQPSK) or GMSK, from a few kbps to several Mbps. Example: the EnduroSat S-band radio listed as KSATlite-compatible receives BPSK/QPSK.
  • The spacecraft receiver fixes the waveform for the mission. In Case A any waveform fits as long as it stays inside 40 MHz in 2025-2110 MHz; in Case B it must be in KSAT's supported list.

A.6 SDLS - what it adds to the frame

SDLS sits inside the TC frame, between the headers and the trailer:

 | Primary header 5 | Segment hdr 1 | Security header | Frame data (packets) | Security trailer (MAC) | FECF 2 |
                                     SPI, IV,          encrypted and/or        authentication tag
                                     sequence number,  authenticated
                                     pad length
  • Security Association (SA): a one-way cryptographic session with fixed algorithm, key, header and trailer sizes. It is selected by the 16-bit SPI in each frame and bound to one or more virtual channels (or MAP IDs for TC).
  • Services per SA: authentication only, encryption only, or authenticated encryption (AES-GCM is the usual choice; CCSDS 352.0-B lists the recommended algorithms).
  • What the MAC covers: the frame primary header (with an authentication bit mask to ignore fields that change in transit), the segment header, the security header and the frame data. Headers are authenticated but never encrypted, so SCID, VCID and lengths stay readable to any station.
  • Replay protection: the sender increments a sequence number per frame; the receiver rejects frames outside a configured window. Size the window for retransmissions and lost frames.
  • Not covered: the CLTU start sequence and coding, the Frame Error Control Field (FECF), the Operational Control Field (OCF)/CLCW in TM, and the COP control frames (Type-BC: Unlock, Set V(R)). 355.0-B-2 section 2.2.4 states it for TC: no protection for control frames generated for the COP Management Service, nor for frames supplied by external sources on the Virtual Channel Frame (VCF) and Master Channel Frame (MCF) services. An attacker who can transmit may still disturb COP-1 (denial of service) without being able to execute commands.
  • Size: for the Yamcs AES-256-GCM profile, 14 octets of header (2 SPI + 12 IV) and a 16-octet MAC, so 30 octets per frame (see the pipeline size table).

SDLS Extended Procedures (355.1-B-1) add the management plane: key management (upload of session keys encrypted under pre-loaded master keys, i.e. over-the-air rekeying, activation, destruction), SA management (create, start, stop, rekey, expire) and monitoring and control (security event reports). Without them, keys and SAs must be preloaded before launch and cannot be rotated in orbit.

A.7 Why it matters with a shared ground segment

  • Both AWS and KSAT encrypt the ground leg (agent KMS key, VPN). Neither can protect the space leg: the uplink is radiated in clear from a 5.4 m or 3.7 m dish, and the provider's equipment handles the decoded signal (Case B) or IQ that is trivially demodulated (Case A).
  • Without on-board authentication, anyone in view of the spacecraft with an S-band transmitter and the (often published) frame format can inject or replay commands. Encryption also keeps command content and operational patterns private.
  • With SDLS the spacecraft only executes frames carrying a valid MAC and a fresh sequence number, and the keys never leave the operator. That is what makes a shared, third-party ground segment acceptable for command and control.
  • Regulation points the same way: the European Union (EU) Network and Information Security 2 (NIS2) directive lists the space sector (operators of ground infrastructure) among its essential sectors, and United States (US) Space Policy Directive-5 (2020) recommends command authentication or encryption. National space authorities can also impose command-link protection in the operating licence [verify with CNES/ANFR for a French licence].

Practical cautions:

  • Pin and patch CryptoLib. Several memory-safety advisories (heap and stack buffer overflows reachable from crafted TC or AOS frames) were published in 2025-2026 for releases 1.3.x and 1.4.0 (advisories). The on-board frame parser runs on attacker-reachable input: track releases and fuzz it.
